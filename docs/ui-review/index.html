Ourlime UI Review

Bug fixes from tester reports, a cleanup of crowded filter screens, a page-by-page polish pass and a production performance audit of the Android app and the website.

Mobile app

E-Projects: three rows of chips become one Filters button

Status, role and sort each had a full chip row, plus an Asc/Desc toggle. They now sit in a bottom sheet, with a count on the button and a removable chip for each active filter. Sort and direction merged into plain choices such as Name A–Z. The empty band above the header is also gone: the page was adding the status-bar inset twice.

Task details: typing stays visible above the keyboard

Raushawn could not see what he typed. On Android the keyboard covered the comment and log-time fields inside the sheet. The sheet now lifts above the keyboard.

Project settings: delete button stays inside the sheet

Delete Entire Project spilled out below the sheet. The sheet now scrolls and keeps every control inside it.

Project activity reads as plain English

Recent Activity showed internal keys like add_subtask and time, twice per entry. It now reads “added a subtask”, “commented”, “logged time”.

Community posts: comment and share counts survive a refresh

Chris reported counts disappearing. The app saved community comment and share counts in the wrong place and read them from a field nothing writes, and the card kept whatever number it first loaded. Counts now come from the same counter the website uses, comments are counted directly, and the card follows the refreshed number. This post has one comment and one share.

Hosting an event: crop the cover, add a poll

Picking a cover only showed a file name, with no preview and no way to crop. The photo now opens the crop screen, then shows as a preview with Crop, Replace and Remove. Chris’s suggestion is in too: a Yes/No Add a poll? toggle that creates a community poll closing when the event starts.

Blogs: one row of categories

The page stacked a type toggle, categories and a long tag row before any content. Categories stay on the page; type, sort and tags (pick several) moved into the existing filter button, which now shows a count.

Admin: Users and Reports

Two labelled chip rows on each screen became one Filters button. Labels such as under_review now read “Under review”.

Website at phone width

Desktop and tablet layouts are unchanged. Below 640px the same controls move into a bottom sheet behind one Filters button.

E-Projects

Three full-width dropdowns and a direction button took five rows before the first project.

Blogs

Type, sort and all popular tags sat above the posts, and the page said No blogs found while it was still loading. It now says “Loading blogs…”, and a blank tag pill is gone.

Admin pages

Users had four wrapping dropdown buttons. Reports had three labelled dropdowns, and its tab row broke words mid-way (“Repo / rts”). Activity Logs had two fixed-width dropdowns over three rows.

Who can see what

Each page’s availability is set by admins in Page Access. Restricted pages were only half enforced: the app’s tab bar ignored the settings, and both the app and the website drew restricted pages behind a see-through overlay while linking to them from every menu. Now a page someone can’t open is neither listed nor rendered for them. The screenshots below were taken with this admin account temporarily treated as a regular user.

App: tabs and menu only list what the account can open

The Limes tab matched no setting because tab paths are capitalised (/Limes), so admin-only Limes stayed open to everyone. The same mismatch hid the website’s /messages and /profile/settings settings from the app. Restricted tabs and menu items are now removed, the blocking screen is fully opaque, and Limes videos never play behind it.

Website: restricted pages are never rendered or linked

The overlay was 50% black with blur, so the restricted page still rendered and loaded its data underneath, and greyed-out links stayed in the top bar, feed tabs, profile menu, bottom bar and Games card (which offered admin-only Trini Wordle). Restricted pages are now withheld until access is confirmed, every nav hides them, and the last known settings are cached so this check doesn’t slow the first paint.

Communities

Comment counts agree everywhere, and posts load faster

The website increased one field when someone commented and displayed a different one, while the app wrote a third. Both now count the comments themselves, so the app, the website and the database agree. The website’s community posts were built with about five database reads per post; they now use a handful of batched reads, and a second call that re-read every post and every like counter in all communities was cut down to this community only. Moderated (hidden) community posts were also still shown on the website because the hidden flag was dropped; they are now filtered.

  • App directory: the Communities list made six database round trips one after another. Independent ones now run together (13.5 s → 10.8 s on the emulator), and the list is now warmed in the background at startup like the feed, so it opens filled.
  • Website community page: posts arrive in about 3 s on the local development server after the first compile.

Fixes without a screen

  • Chat archive. Unarchiving from inside a chat now takes it out of Archived, and it stays out after a restart. The list used to rebuild from a stale local copy.
  • Manage Jobs crash. The screen crashed on open because the app’s runtime lacks Promise.finally. All 16 uses across the app were replaced.
  • Status bar. After visiting Limes, the clock and battery icons turned white on light screens such as Communities. Limes now sets its dark status bar only while it is open.
  • Event poll toggle. The selected Yes/No option no longer stays faded after tapping.
  • Members count. The project stat now counts accepted members only, matching Team Members.
  • Roles and permissions guide. A rule file for AI agents in both repos explains that “Administrator Access Required” pages, such as a shared Lime, are an admin choice and not a bug.

Polish pass

A page-by-page sweep of both apps for small, high-impact fixes: honest loading states, readable labels, theme colors, touch targets and spacing. Layouts, navigation and page structure were left alone; anything bigger is listed under Recommendations.

Events and Market say “Loading” instead of “0”

While data was on its way, Events read 0 upcoming community and public events, and Market and E-Hub read 0 listings loaded. Both looked like empty pages. They now say they are loading until the data arrives. Jobs got the same treatment on both platforms.

Settings: account fields stay together

The policy links sat between First Name and Last Name. They now follow the account fields, in the same tab.

Courses and cart read cleanly

The course catalog showed Programming three times because the category list has duplicate names. The saved cart opened with a fragment, “synced. Items do not reserve stock.” Each status is now a full sentence.

Website: greeting, sign-in hints and status chips

E-Learning greeted people by email address and showed Don&apos;t in a course message. Help showed Sign in required on every card to people already signed in. E-Projects chips showed raw values such as active and owner.

Full test pass

Every website route (140) was loaded signed in on a production build, checking for failed requests, console errors and unexpected redirects. Every app screen (62) was opened by deep link on the production bundle. Each bug below was fixed, confirmed in development mode, rebuilt for production and retested before moving on.

Website fixes

  • You were signed out while browsing. Two causes: re-syncing a session rewrote its start time, so the duplicate-session cleanup deleted the live one; and opening /login while signed in (which the product edit page did while auth was still restoring) ended the session. Both fixed, and the security log no longer gains a login entry per page view.
  • Ads pages could not tell who you are. Eight ads API routes checked the browser-only Firebase user on the server, which is always empty. They now read the session cookie or a sign-in token. My Bookings shows its empty state instead of an error.
  • My Offers asked for hostId=undefined and got a server error. It now looks up your host profile by your account.
  • Project invites failed with 503. The shared server code used a second copy of the admin SDK that was never started; it is now started on demand.
  • Page Access showed “Unauthorized” on load because it read the admin’s ID before the profile had loaded.
  • A missing support ticket returned a server error (500) instead of not found (404). Blog cards without a cover requested an image that doesn’t exist; they now use a default cover. The instructor access page no longer redirects you away after 3 seconds. The Discover friends list waits for sign-in before loading.
  • Missing database indexes broke course discussions, seller orders, ad offers and the host list. Seven composite indexes were created and added to firestore.indexes.json.

App fixes

  • Website links open the right screen. Help, Policies, Privacy, Terms, Settings, Saved, Games, Wallet, Ads, Chat and admin links used to fall through to the home feed.
  • Market prices and sellers. Items without a stored currency showed no price and counted as unavailable; they now show “$700.00”. Seller names fall back to the seller’s profile name.
  • Admin Stickers: the Packs/Stickers tabs sit under the header, and search reads “Search sticker packs”. Help hides the sign-in hint once you are signed in.
  • Type check failed after the route list grew: notification routing now picks its fallback in a way the compiler can handle. All 22 routing tests pass.

Follow-up: making the app match the website

  • Course discussions are one system again. Posting on the website had been failing, because security rules block browser writes. The website now posts and replies through the same server functions as the app. The app gained replies (tap a discussion to open it and reply), shows the two older website posts with their titles, and fills in missing author names from profiles. Old posts stored the author’s email as their name; that is no longer shown. Replies will also store the author’s name once functions are next deployed.
  • Privacy, Terms and Delete Account in the app. The embedded website page crashed (“Application error”) in the app’s web view, because the site called a native-bridge function that wasn’t there. Both sides are fixed. Links inside these pages now open the matching app screen, for example “Open account settings” opens Settings. The website hides its own header and navigation in the app once the website update is deployed.
  • Discussion composer no longer sits under Android’s gesture bar.
  • Checked, no change needed: admin lists load 6 s after a cold start on a healthy device (the 80 s earlier came from an overloaded emulator). /notifications and Limes settle within about 4 s, and Limes preloads only the first video. The earlier 48–53 s figure was the crawler’s wait, not page load.
  • Server function tests ran on the local emulator: the discussion and reply tests pass, and so do both project-route tests, which needed their mocks updated. Six older tests that failed because their mocks predated the app’s switch of Firebase SDKs were repaired afterwards, so the suite passes 47/47. One concurrency test is flaky on the emulator (it passed on the rerun). The 13 comment-counter tests pass.
  • Ads marketplace backend now runs on the admin SDK with ownership checks on every ads route. Ads is still “Coming Soon” on both platforms; payments and pricing are not built yet.

Expected, not bugs: the ads host dashboard and verification pages send non-hosts home, and My Offers and Become a Host show a 404 from the host lookup when you aren’t a host yet. A development-client-only crash (“App react context shouldn’t be created before”) appeared when the test script closed the app’s last screen and then reopened it; release builds don’t include that code.

Round 3

Chat selection redesign, trimming for every video upload, an unread-badge fix, three data bugs, and the security lockdown work. Everything here was checked on the Android emulator and the website dev build, without writing real data.

Selecting chats

Long-pressing a chat used to turn the header solid green with six unlabelled icons: a bookmark meant “pin” and a check meant “mark read”. The header now stays on the page surface with “1 selected” and a Select all / Clear button. The actions sit in a floating bar with labels (Pin, Archive, Read or Unread, Mute and Delete in red), all from one outline icon set. Each label says what a tap will do, for example Unpin when every selected chat is pinned. Pinned chats in the list show a pin instead of a bookmark.

Trim any video before posting

The trimmer used to open only when a video was over the limit (2 minutes for posts, 30 seconds for Limes). Every selected video now has a Trim button in the feed composer and the Lime uploader, on the website and in the app. The trimmed copy replaces the original in place, and Cancel keeps the original. Two bugs in the app’s trimmer, which chat shares, are fixed. Dragging a handle was taken over by the selection window, so the handles didn’t move. On Android the right handle sat in the back-gesture zone, so dragging it closed the trimmer.

Fixed

  • The Chat badge showed 6 with nothing unread. It added up unread messages across every chat, including one archived chat with 6 unread. On the app tab and the website’s two chat badges, it now counts chats with unread messages and skips archived ones, the same rule as the Unread filter.
  • Removing one photo from an album deleted the whole album. Only that photo is removed now.
  • Deleting a job left its applications behind, and the jobs delete page always showed 0 applications. Both are fixed.
  • /forgot-password no longer requests a missing image.

Security

The live database rules turned out to be Firebase’s open “test mode” template, so anyone could read or change any data; the repo’s ruleset had never been deployed. A full backup was exported (65,111 documents). The holes in the repo rules are closed, including a way for any user to make themselves an admin, and 76 rules tests prove it. Every website server route moved to the admin SDK with ownership checks. Client writes the new rules would block now go through the server: notifications, counters, events, blogs, e-learning, registration checks and listing status. Private personal data (email, phone, birth date, guardian details, moderation notes) moves to an owner-only document. Friends-only posts are readable only by friends and private (“Only me”) posts only by the author. The rules, migration and server-function suites pass on the emulator (89, 47 and 24 tests). The website’s server code now follows the same rule, so friends can no longer like or comment on “Only me” posts. The website composers offer Public, Friends and Only me, matching the app, and post cards show the real audience.

The app also gained a minimum-version check. It reads siteConfig/mobileApp. When the installed build is older than minimumVersion, a blocking “Update Ourlime” screen links to the store. If the setting is missing or can’t be read, the app keeps working. Builds released before this one don’t contain the check, so testers need this build before the rules go live.

Round 4: sharing, E-Learning and the website at phone width

Bugs found on the live site after the 14 October deploy, an E-Learning rebuild for wide monitors, and the app’s filter cleanup brought to the website at phone width. Everything was checked on the website build and, for the app, in code; nothing was written to production data.

Sharing

  • Profile pictures were missing from the Share list. The friends list skipped the photo lookup to save time, so anyone whose photo lives only in their photo gallery showed the default avatar. It always looks the photo up now: 7 of 9 friends in the test account show their real photo, and the other 2 have none.
  • A share with a note arrived as two messages. The link and the note were sent separately. They now go as one message, and chat shows the Lime or post card with the note under it in the same bubble, like WhatsApp and Instagram. A share without a note still shows the bare card. Website and app both changed.

E-Learning

On a wide monitor the page stretched edge to edge: the hero, course messages and course grid ran the full width, while the welcome card sat in a narrow 1200px column, and the tutors were a lone column with empty space beside them. The page is now one centred 1400px column, like the feed. The welcome card holds the photo, stats and section links (Courses, My Learning, CXC Hub, plus the instructor links). Desktop shows the course grid beside a sidebar with Browse by category (real categories with course counts, each a working link) and Tutors. The grid shows 9 courses with “View all 27 courses”, and the page scrolls normally instead of scrolling inside fixed-height boxes. On phones the header no longer covers “Back to Home”, and “0 hours” is hidden.

Course Messages and Tutors were placeholder text (“Dr. Sarah Johnson”, “Prof. David Chen”). They now show real data, as the app does: announcements from the member’s enrolled courses, and verified instructors. Duplicate instructor profiles are shown once, on the website and in the app.

Website at phone width

Communities, Events, Jobs and Market now use the same Filters button and bottom sheet as Blogs and E-Projects below 640px. Desktop layouts are unchanged. The sheet now opens above the site header, which used to show over its dimmed background (also on Blogs, E-Projects and the admin pages).

  • Communities: Community of the week is a compact card instead of a full-screen hero. One scope row (All, Joined, Friends, New, Mine) replaces the arrow carousel. Search, Filters and Create share a row. The sheet holds visibility, category, sort and layout, matching the app.
  • Events: the hero clears the header and is shorter, upcoming events swipe sideways, and sort, view, category and tags moved into the sheet.
  • Jobs: one-row search, one row of categories, the two Create buttons side by side. The Professional tab said “Showing 2 results” with nothing listed; the count and empty state now follow the selected tab.
  • Market: three toolbar rows became one. Product cards no longer break words (“SPOR / TS”, an “Add” button spelled down the side).
  • Home: scrollbars under the feed chips and composer buttons are gone (the class that hides them was never defined).
