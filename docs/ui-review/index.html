Ourlime UI Review

Bug fixes from tester reports and a cleanup of crowded filter screens, shown as before-and-after screenshots from the Android app and the website at phone width.

Mobile app

E-Projects: three rows of chips become one Filters button

Status, role and sort each had a full chip row, plus an Asc/Desc toggle. They now sit in a bottom sheet, with a count on the button and a removable chip for each active filter. Sort and direction merged into plain choices such as Name A–Z. The empty band above the header is also gone: the page was adding the status-bar inset twice.

Task details: typing stays visible above the keyboard

Raushawn could not see what he typed. On Android the keyboard covered the comment and log-time fields inside the sheet. The sheet now lifts above the keyboard.

Project settings: delete button stays inside the sheet

Delete Entire Project spilled out below the sheet. The sheet now scrolls and keeps every control inside it.

Project activity reads as plain English

Recent Activity showed internal keys like add_subtask and time, twice per entry. It now reads “added a subtask”, “commented”, “logged time”.

Community posts: comment and share counts survive a refresh

Chris reported counts disappearing. The app saved community comment and share counts in the wrong place and read them from a field nothing writes, and the card kept whatever number it first loaded. Counts now come from the same counter the website uses, comments are counted directly, and the card follows the refreshed number. This post has one comment and one share.

Hosting an event: crop the cover, add a poll

Picking a cover only showed a file name, with no preview and no way to crop. The photo now opens the crop screen, then shows as a preview with Crop, Replace and Remove. Chris’s suggestion is in too: a Yes/No Add a poll? toggle that creates a community poll closing when the event starts.

Blogs: one row of categories

The page stacked a type toggle, categories and a long tag row before any content. Categories stay on the page; type, sort and tags (pick several) moved into the existing filter button, which now shows a count.

Admin: Users and Reports

Two labelled chip rows on each screen became one Filters button. Labels such as under_review now read “Under review”.

Website at phone width

Desktop and tablet layouts are unchanged. Below 640px the same controls move into a bottom sheet behind one Filters button.

E-Projects

Three full-width dropdowns and a direction button took five rows before the first project.

Blogs

Type, sort and all popular tags sat above the posts, and the page said No blogs found while it was still loading. It now says “Loading blogs…”, and a blank tag pill is gone.

Admin pages

Users had four wrapping dropdown buttons. Reports had three labelled dropdowns, and its tab row broke words mid-way (“Repo / rts”). Activity Logs had two fixed-width dropdowns over three rows.

Fixes without a screen

  • Chat archive. Unarchiving from inside a chat now takes it out of Archived, and it stays out after a restart. The list used to rebuild from a stale local copy.
  • Manage Jobs crash. The screen crashed on open because the app’s runtime lacks Promise.finally. All 16 uses across the app were replaced.
  • Status bar. After visiting Limes, the clock and battery icons turned white on light screens such as Communities. Limes now sets its dark status bar only while it is open.
  • Event poll toggle. The selected Yes/No option no longer stays faded after tapping.
  • Members count. The project stat now counts accepted members only, matching Team Members.
  • Roles and permissions guide. A rule file for AI agents in both repos explains that “Administrator Access Required” pages, such as a shared Lime, are an admin choice and not a bug.

Still open

  • “Unknown Author” on 4 blogs. Those posts have an empty author in the database, so there is no name to show. It needs a data fix.
  • Limes tab is not gated. The Limes setting is admin-only, but the tab ignores it while a shared Lime respects it. Gating the tab would hide Limes from every non-admin, so that is a product call.
  • Website comment counts on community posts read the same unset field the app used to. The app is fixed; the website is not yet.
  • Slow loads on Communities and some project actions, seen on the emulator and in Raushawn’s video.

The round “N” badge in the website screenshots is the Next.js development indicator and does not appear in production.
