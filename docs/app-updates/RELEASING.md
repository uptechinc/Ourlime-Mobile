# Releasing an Android update

Two kinds of release, one experience for users. Pick by what changed:

| Changed | Release type | Users get |
|---|---|---|
| JavaScript/TypeScript, images, copy only | **OTA** (EAS Update, `OTA.md`) | Background download, then "Restart to apply" |
| Anything native: new/updated native packages, `plugins/` Kotlin or config plugins, permissions, `app.json` native keys, Expo SDK bump | **APK** (this file) | "Update available", an in-app download, then Android's installer |

If unsure, ship an APK. An APK always works; an OTA that needs missing native code can crash, and expo-updates then rolls it back.

## Production release checklist (Play, `com.ourlime.mobile`)

Every native release is a production build for the Play app. There are no tester or sideload releases any more, and nothing is built on EAS.

1. **Bump `expo.version` and `expo.android.versionCode` in `app.json`.** The versionCode must be greater than the last one uploaded to Play.
2. **Write `lib/releaseNotes.json`** with what changed since the last release (see step 2 of the legacy list below).
3. **Build locally:** `npm run build:local` builds `Ourlime-<version>-vc<code>.aab` for `com.ourlime.mobile`, signed with the Play upload key from `credentials.json`. The script stops if the key is missing or the SHA-1 isn't `8E:EE:1D:44…`. For a test install of the same production build, use `npm run build:local:apk`.
   - First time only: run `npx eas-cli credentials -p android`, then **production** → **credentials.json** → **Download credentials from EAS to credentials.json**. `credentials.json` and `credentials/` are git-ignored.
4. **Upload the .aab in Play Console** (a new Production release), paste the notes, and roll it out.
5. **Once Play shows the update as live, announce it:**
   ```bash
   GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json node scripts/publish-android-release.cjs
   ```
   This uploads nothing. It writes `latestVersion`, `latestVersionCode`, `releaseNotes`, `releasedAt`, `androidStoreUrl` (the Play listing) and `sideloadUpdates: false`. Open apps show "Update available" and the button opens Play. `notifyAppUpdate` sends the push once per versionCode. Run `--dry-run` first.

## Legacy: sideload APK release (not used)

Kept only for reference (`publish-android-release.cjs --sideload --apk …`). Only locally built APKs could be published this way. EAS cloud builds are signed with a different key (`86437d…`), so they can't install over the sideloaded builds that have the in-app updater.

1. **Bump both versions in `app.json`.** The Gradle file is regenerated by `expo prebuild`, so edit only `app.json`:
   - `expo.version`, e.g. `1.1.2` → `1.2.0`. With `runtimeVersion: appVersion`, this also gives the release its own OTA runtime.
   - `expo.android.versionCode`, e.g. `4` → `5`. It must be strictly greater than the published `latestVersionCode`, or neither Android nor the app accepts it.
2. **Write the release notes in `lib/releaseNotes.json`** (`version`, `versionCode`, and up to 12 `notes`, each under 240 characters). List what changed since the last published release in plain words, one bullet per feature or fix. The app bundles this file and shows it in "What's new" after the update, and the publish script uses it as the default `--notes`.
3. **Build:** `npm run build:local`. This produces `Ourlime-dd.mm.yy.apk` in the repo root.
4. **Check signing.** The new APK must be signed with the same key as installed builds, or Android refuses to update and the app shows "not signed with Ourlime's key". The dry run prints the certificate. Today every build shows `fac61745…033b9c` (see "Signing" in `README.md`).
5. **Dry run:**
   ```bash
   node scripts/publish-android-release.cjs --dry-run
   ```
   It refuses when:
   - the APK's package, versionName or versionCode doesn't match `app.json` (for example, a stale APK built before the bump)
   - the versionCode isn't greater than what Firestore already has
6. **Publish** (needs a service-account key; never commit it):
   ```bash
   GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json node scripts/publish-android-release.cjs
   ```
   The script first uploads `app-releases/android/<versionCode>/Ourlime.apk`, then writes these fields into `siteConfig/mobileApp`: `latestVersion`, `latestVersionCode`, `apkUrl`, `apkSha256`, `apkSizeBytes`, `releaseNotes`, `releasedAt` and `sideloadUpdates: true`.
7. **What users see:**
   - Open apps show the sheet within seconds, through the live Firestore listener.
   - Once `notifyAppUpdate` is deployed, closed apps get the `app_update` push.
   - Everyone else sees the sheet on next launch or foreground.
8. **Verify on a device** with `VALIDATION.md` (at least items 1, 4 and 5).

## When to raise `minimumVersion`

`minimumVersion` blocks every older build with a full-screen "Update Ourlime" screen. On sideload builds with the in-app updater, that screen downloads and installs the APK itself; otherwise it opens the APK link or the store. Raise it only when old builds would break, for example:

- server rules or Cloud Functions changed so old clients fail
- a security fix
- a data-format change

Steps:

1. Publish the APK first, and make sure it installs (steps above).
2. Then raise it: `node scripts/publish-android-release.cjs --minimum-version 1.2.0 …` on the release itself, or edit `siteConfig/mobileApp.minimumVersion` in the console.
3. Never set it higher than the newest published version, or every device is blocked with nothing to update to.

## Kill switch

Set `sideloadUpdates: false` in `siteConfig/mobileApp` to stop in-app APK downloads (for example, a bad APK was published). "Update now" then opens the store link instead. To withdraw a release completely, set `latestVersionCode` back to the installed version.

## Play Store builds

Set `expo.extra.distribution` to `"play"` before building. The `withOurlimeAppUpdate` plugin then leaves out `REQUEST_INSTALL_PACKAGES` (Play policy). The app falls back to the existing `market://` / Play link for both "Update now" and the blocking screen. OTA updates work the same way.
